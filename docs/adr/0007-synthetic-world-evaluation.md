# 0007. 평가는 정답을 심은 합성 세계 + 수기 세트 + 백테스트

## 맥락
실제 회의록·예산서에는 정답 라벨이 없고, 개발 컨테이너는 공공 API에 접근할 수 없었습니다. 그렇다고 평가 없이 프롬프트·파서·랭커를 바꿀 수는 없습니다.

## 결정
세 층으로 나눠 평가합니다.
1. **합성 세계**(`demo/synth.py`): 시드 고정. 21개 사업 원형으로 "실제 사업"(truth)을 만들고, 그 생애를 의회 회의록 → 세출예산서(텍스트 PDF·스캔 PDF·HWPX) → 발주계획 → 사전규격 → 입찰공고 레코드로 렌더링합니다. 동명 기관, OCR 잡음, 단위 혼동, 약한 발언, 공고로 이어지지 않는 사업, 무관한 공고를 일부러 넣습니다. 정답이 있으므로 추출 P/R, 필드 정확도, 연결 쌍 P/R, OCR CER을 계산합니다.
2. **수기 세트**(`eval/golden/realistic.jsonl`): 생성기와 다른 사람이 쓴 듯한 문장 14건. 합성 세계가 생성기와 추출기의 "같은 머리"를 재는 문제를 드러내기 위한 세트입니다(규칙 기반 추출기 재현율 61.5%).
3. **백테스트**(`pipeline/backtest.py`): 기준일로 시계를 되돌려 "공고가 난 사업 중 몇 %가 그 전에 신호를 가졌나, 얼마나 일찍"을 계산하고, 첫 신호 유형별 전환율을 랭킹의 `conversion` 특징 보정에 씁니다.

CI는 합성 세계 기준 임계값(추출·연결 P/R ≥ 0.95, OCR 금액 토큰 ≥ 0.98, CER ≤ 0.03)을 **품질 게이트**로 씁니다.

## 결과
- 얻은 것: 파서·프롬프트·연결 규칙을 바꿀 때마다 같은 정답으로 비교(`mulmit eval all --record`, 운영 콘솔 "평가·백테스트").
- 치른 비용: 합성 세계 점수는 실제 정확도가 아닙니다. 문서와 화면에 이 점을 명시합니다.

## 다시 볼 조건
실제 데이터가 들어오면 검토 대기열에서 사람이 판정한 결과를 정답 세트로 쌓아 수기 세트를 대체합니다.

# 0009. 지자체 누리집 게시판은 예의 바른 크롤러로 수집한다

## 맥락
지방재정365가 법정 예산서를 모아 주지만, 추경 예산서·사업설명서·기본계획처럼 각 기관 누리집의 "예산 공개" / "고시·공고" 게시판에 HWP·PDF 첨부로만 먼저 올라오는 문서가 많습니다. 여기에는 API가 없고 HTML뿐입니다. 전국 지자체·의회를 합치면 수백 개 호스트이고, 한 기관이라도 차단하면 그 기관의 신호가 통째로 사라집니다.

## 결정
- **범용 게시판 크롤러 하나 + 기관별 설정**(`sources.config`): 목록 URL, 상세·첨부 링크 패턴, 게시글 ID 파라미터, 제목 키워드. 대부분의 게시판은 "제목 링크와 날짜가 있는 표(또는 목록)"라는 같은 모양이라, 기관 추가는 코드가 아니라 설정입니다.
- **예의**: robots.txt를 호스트마다 한 번 받아 따릅니다(RFC 9309: 4xx는 규칙 없음, 5xx·접속 불가는 이번 실행에서 그 호스트 전체 금지). 모든 요청은 `<수집원>@<호스트>` 키의 공유 토큰 버킷을 거치고, 호스트별 최소 간격(기본 1초)을 둡니다. User-Agent에 연락처를 넣습니다.
- **증분**: 게시판은 최신순이므로 목록의 가장 오래된 글이 수집 창보다 이전이면 다음 페이지로 가지 않습니다(수집 커서가 3일 겹침을 둡니다).
- **믿지 않는 파일**: 첨부는 스트리밍하면서 크기 상한(기본 50MB)을 넘으면 끊고, 형식은 서버의 Content-Type이나 파일명이 아니라 파일 앞부분 바이트로 판단합니다(PDF, HWP5, HWPX). 로그인 페이지를 `.pdf`로 내려주는 사이트가 실제로 있습니다.
- 데모의 예산서는 기관별 **합성 누리집**(`*.gov.example`, `httpx.MockTransport`)에 게시되고 이 크롤러로 수집됩니다. 실제 크롤러 코드 경로가 데모와 테스트에서 매번 돕니다.

## 결과
- 얻은 것: API가 없는 문서원을 코드 수정 없이 추가할 수 있고, 차단·중복·대용량 파일에 안전합니다. 합성 누리집 25개 문서를 수집했을 때 원본과 바이트·제목·날짜·회계연도가 모두 일치했고, 평가 결과는 이전과 동일했습니다.
- 치른 비용: 실제 기관 게시판에는 개발 환경에서 접속하지 못해, 기관별 설정은 운영에서 하나씩 확인해야 합니다. JavaScript로만 목록을 그리는 게시판은 이 크롤러로 읽을 수 없습니다(헤드리스 브라우저가 필요).

## 다시 볼 조건
JS 렌더링 게시판 비율이 높으면 해당 호스트에 한해 Playwright 기반 수집기를 별도 워커로 둡니다.

# 0002. LLM 추출은 원문 근거 검증을 통과해야만 쓴다

## 맥락
영업 담당자가 "3억 5천만 원, 내년 상반기"를 믿고 움직이려면 그 숫자가 원문에 있어야 합니다. LLM은 금액 단위(천원 표 vs 본문 억 원)나 상대 연도("내년")를 틀리기 쉽고, 이런 오류는 겉보기에 그럴듯합니다.

## 결정
`domain/grounding.py`의 검증기를 LLM과 규칙 추출기 **양쪽 출력에 똑같이** 적용합니다.
1. **근거 문장**: 추출이 인용한 문장을 공백·기호를 정규화한 원문에서 찾습니다(정확 일치 → rapidfuzz 부분 정렬 88점 이상). 찾은 위치는 원문 오프셋으로 되돌려 저장합니다. 하나도 못 찾으면 `rejected`.
2. **금액**: 인용 문장과 `budget_text`에서 한국어 금액 파서(`krw.py`: 억·만·천원 표 단위·한글 숫자)로 다시 읽은 값과 일치해야 합니다. 예산서 표 안에서는 단위 없는 숫자도 표 머리의 `(단위: 천원)`로 해석합니다.
3. **연도**: "내년·'27년·하반기"를 문서 날짜 기준으로 다시 풀어 모델이 낸 연도와 비교합니다.
4. **기관**: 발언 기관·언급 기관을 기관 사전(동명 기관 `중구` 등은 모호로 처리)으로 확인합니다.

문제가 하나라도 있으면 `needs_review`로 운영 콘솔의 검토 대기열에 들어가고, 사람이 고친 결과는 연결 작업을 다시 돌립니다.

## 결과
- 얻은 것: 화면의 모든 숫자에 원문 위치가 붙습니다. 모델을 바꾸거나 프롬프트를 고쳐도 같은 검증기로 비교할 수 있습니다.
- 치른 비용: 정당한 의역 추출도 가끔 검토로 빠집니다(재현율 손실). 검토 대기열을 운영해야 합니다.

## 다시 볼 조건
검토 대기열 승인율이 계속 95%를 넘으면 해당 사유(예: `year_unverified`)는 자동 승인으로 완화합니다.

# 0004. 검색은 PostgreSQL 하나로: pgvector + pg_trgm

## 맥락
필요한 검색은 세 가지입니다. (1) 회사 소개 ↔ 기회의 의미 유사도, (2) 사업명 키워드 매칭(한국어), (3) 연결 후보 찾기(기관·분야·기간으로 좁힌 뒤 유사도). 데이터 규모는 전국 지자체 기준 연간 수십만 문서, 신호·기회는 그보다 한 자릿수 적습니다.

## 결정
- **pgvector** HNSW 인덱스(`vector_cosine_ops`, m=16, ef_construction=64)로 신호·기회 임베딩 검색.
- PostgreSQL에는 한국어 형태소 기반 FTS 파서가 기본 제공되지 않으므로 **pg_trgm GIN 인덱스**로 제목 `ILIKE`/유사도 검색을 인덱스로 처리합니다. 조사 차이는 도메인 동의어 사전(`synonyms.py`)과 정규화로 보완합니다.
- Elasticsearch/OpenSearch는 두지 않습니다.

## 결과
- 얻은 것: 트랜잭션 안에서 필터(기관·지역·단계·예산)와 벡터 검색을 한 쿼리로 결합, 인프라 하나 감소(Cloud SQL이 두 확장을 모두 지원).
- 치른 비용: 형태소 분석 기반 랭킹(BM25)이 없습니다. 키워드 점수는 애플리케이션에서 계산합니다.

## 다시 볼 조건
회의록 전문 검색(수백만 청크 대상 자유 검색)을 제품 기능으로 열 때, 은전한닢(mecab-ko) 분석기를 쓰는 OpenSearch를 별도 읽기 모델로 추가합니다.
